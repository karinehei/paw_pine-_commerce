# Localization (FI / EN / SV)

UI copy is translated from **repository dictionaries**. There is no paid translation API, TMS, or SaaS localization platform.

## Dictionaries

```
locales/fi.json
locales/en.json
locales/sv.json
```

`src/lib/i18n/messages.ts` loads those files and exposes `getMessages(locale)`. Components call `t.checkout`, `t.searchResult(count, term)`, and so on. They do not branch on `if (locale === "fi")`.

Finnish is the **default market language**. Every public URL is prefixed:

| Language | Prefix    |
| -------- | --------- |
| Finnish  | `/fi/...` |
| English  | `/en/...` |
| Swedish  | `/sv/...` |

`/` 308-redirects to `/fi`, or to the `paw_pine_locale` cookie when it is a known locale. Unknown two-letter prefixes such as `/de` are **404**.

The language switcher keeps the current path and query (`/en/products/oakwood-chew-ring` → `/sv/products/oakwood-chew-ring`).

## Shopify catalogue copy

Do not invent translations for live Shopify product fields.

The Storefront client already sends `@inContext(language: $language)` (`FI`, `EN`, or `SV`). If the shop has Shopify Markets / translated resources, those strings appear. If not, Shopify returns the source catalogue text. The UI chrome is still localized.

The **demo** catalogue includes in-repo Finnish product titles for hiring review. Swedish demo products stay in the English source language for the same reason we do not fabricate Shopify copy.

To connect Markets later: keep handles stable, keep this routing, and translate products in Shopify admin. No third-party translation vendor is required.

## SEO

Canonicals include the locale prefix. `hreflang` lists `fi`, `en`, `sv`, and `x-default` (Finnish). The sitemap lists all three. Unprefixed catalogue URLs are not indexed; they redirect.
